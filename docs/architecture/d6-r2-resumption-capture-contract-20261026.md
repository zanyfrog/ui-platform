# D6-R2 resumption — complete capture/refusal obligations

2026-10-26. Specification only. **No R2 runtime implementation or executable capture closure is admitted because Gate A has not passed.** Does not broaden accepted P2/P3 semantics or accepted L1/L2/L3 behavior.

## Immutable candidate requirements

A candidate must preserve the exact original request/generation, permanent Application owner, owner-qualified Page ID, committed Page hash, unique stable saved Card node, original context/source/selection generations, and canonical implementation identity as distinct data. Source ownership cannot be retargeted to the canonical package Card ID. Browser identity fields are comparison inputs, never grants.

Resolve the Application and saved Page through existing authoritative owners; reject repair-only identities, duplicate/absent Page membership or changed original ownership. Capture all required Page role bytes, never drafts or generated defaults. Use the existing hardened shared parser/validator for unique committed node and Component identity and existing canonical package settings semantics; no duplicate parser/catalog or current editor inference.

The initial selected Card and its entire applicable Page/Card closure must fit the exact P2 native implementation and P3 restricted static presentation. Child content, functions, custom CSS, assets, composition, data/action/service/resource dependencies must be fully represented by admitted owners or explicitly refuse. Capturing source bytes is not permission to ignore their semantics. No synthetic Page, default theme, sample values or live resource URL is a substitute.

Bind exact P2/P3 publication IDs, their original owners, selection generations, canonical Definition/package/export/revision and complete immutable indexes/bytes. Independently require the real Application owner to establish current package activation points to that exact package implementation/publication and the applicable presentation selection matches its completed owner version. A P2 or P3 lease proves content and retained provenance, not those current application facts.

Hold one existing correctly ordered recovery-free graph over discovery/capture/revalidation. Public graph-owning readers cannot simply be nested. The owner composition boundary must preserve exact canonical scope, role order, finite waiting, cancellation and callback-once behavior. Every Foundation read/list/root/role must explicitly refuse recovery. No package/catalog refresh, manifest manufacture, re-publication, migration or default recovery fallback.

Return only a server-held immutable metadata index and copy-isolated bytes. Admitted source/publication buffers and caller mutations cannot alter the candidate; frozen wrappers alone are insufficient. Validate source identities/hashes, complete membership, activation and presentation applicability, publication/selection generations and original authority/currentness before return. Bound candidate lifetime by all contributing leases and the original context; expired or superseded outcomes cannot return late success. Disclosure requires separate current authorization.

## Non-disclosing refusals

Required distinctions include invalid original request; owner/Page/node mismatch; missing/duplicate/ambiguous membership; incomplete/unsupported semantic closure; changed Page/hash/activation/publication/selection; absent current activation binding; unqualified owner composition; unavailable/denied authority; expired/canceled/stale context; and R1 busy/unresolved/unsafe/recovery-required admission. Underlying filesystem paths, PID/journal contents and policy payloads must not escape. These are obligations, not newly implemented error codes.

## Missing owner contract — narrow scope

The existing Application/package activation owner must expose a nonrepairing, authoritative read binding:

- Original permanent Application identity and canonical package/Definition/export identity.
- Effective enabled/resolution state and exact selected sealed implementation/publication identity, with an authoritative generation/currentness fence distinct from a package version label, timestamp or P2 selection generation.
- Which existing activation/installation/replacement/migration writers participate and how all relevant mutations are ordered against capture, or an approved equivalent owner publication fence.
- Refusal for unbound legacy activation. No auto-adoption of a P2 selected seal, automatic migration or browser-selected identity.

For presentation, establish an owner-maintained applicability crosscheck between original saved-source context, normal published-version selection and exact P3 seal/selection generation. Existing P3 metadata is a retained completed version, not a fresh normal-active observation.

These are **Application activation/applicability ownership decisions**, not requests to broaden native/package/theme/asset rendering. A source-only implementation may be possible within existing owners and graph mechanisms once the binding semantics/writer coverage are specified; no global lock or recovery model change is inferred. Separate operational publication/activation remains prohibited.

After those facts are available, add read-under-current-admission composition to real P2/P3 owners and source acquisition without weakening their checks, then resume R2's implementation/tests. Do not build a successful candidate by replacing these missing facts with fixture callbacks. A fixture authority may test admission mechanics, but cannot invent production activation provenance.

## Authority separation

Real trusted server request must bind original user/session/revision, registered Application owner and applicable access policy before acquisition and recheck continuity/current invalidation before candidate return. The absence of a qualified adapter alone would require an internal/unavailable production boundary, as the user permits. It is **not** the reason this Gate A fails; the missing activation-to-publication binding is independent.

Future byte disclosure, immutable delivery and native construction require separate current-authority checks. No allow fixture, lease, source hash, seal ID or client context is a production grant.
