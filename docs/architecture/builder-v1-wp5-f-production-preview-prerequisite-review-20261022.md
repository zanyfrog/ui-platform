## Decision

Production Preview needs three independent approvals: coherent source acquisition, current trusted authority with immutable delivery, and admitted native execution/resource closure. None substitutes for another. The shortest useful next increment is an **authority and capture-delivery contract decision**, developed from the existing security prerequisite, using source inspection and authored examples only. In parallel in the roadmap, source-only renderer admission and D6 evidence reconciliation can advance without touching blocked state. This review does not authorize any of those follow-on increments.

Keep saved-artifact Preview unavailable until every lane needed by the selected type is qualified. Accepted Card/Panel fixtures, route inspection and shared shell remain useful foundations, but their synthetic authority and memory transports do not qualify protected production display.

## Lane 2 — trusted authority, channel health and immutable delivery

**Exists.** The security investigation identifies I-AM `SecurityDefinitionStore` as the durable policy/revision authority, development identity as session/expiry/original-user authority and the Application registry as permanent ownership authority. `src/server/v1-development-identity.ts` supplies request-time identity/policy freshness; `src/server/editor-security.ts` has authenticated editor SSE, session binding and event reauthorization. `src/client/artifact-editor/session.ts` provides local generation/invalidation; `transport.ts` uses source events and reconnect reconciliation. These are reuse points. They do not establish an end-to-end authority invalidation feed.

**Missing.** A committed, recoverable authority-owned cursor/change contract across all policy writers; durable commit-to-publish recovery; owner/session replacement and expiry coverage; time-based rights expiry without a policy write; source currentness versus authority invalidation separation; authenticated subject/session/permanent-owner binding; readiness after reconciliation; sequence gaps/duplicates/out-of-order handling; channel-health deadlines and fail-closed behavior. A source watcher, broad workspace event, localStorage signal, policy digest poll or one-process emitter is insufficient. Silently suppressing denied events does not tell a client to hide already displayed bytes.

Architecture must choose a feasible connected-client timing contract. Record commit, send, receive and local hide separately. On processed local invalidation/identity switch, hide before awaiting cleanup; abort pending captures and generation-guard late responses. On detected disconnect/gap/unhealthy authority, hide and require fresh authorization plus explicit Refresh. A silent partition has a health-detection window; frozen browser/compositor pixels and previously disclosed bytes cannot be recalled. No numeric SLA is invented here. If literal zero-delay remote disappearance is mandatory, retain unavailability.

Immutable delivery needs a server-bound ephemeral capture/session with original subject/session/permanent owner, selected identity, renderer/policy versions and validity ceiling. Canonical capture identity includes role bytes, dependency/membership edges, package manifest/activation/executable/style/resource bytes and applicable composition/theme/assets. Authority epoch is separate from content identity. Every capture/resource response rechecks original binding and current permission; an opaque token or hash is not authority. Specify check-to-send admission/cancellation and response race handling. Deliver captured bytes only: no live module URL, asset lookup, dynamic import or fallback discovery. Bound lifetime, bytes and session count; revoke access and discard buffers on expiry/invalidation/disposal. No record transport or effect capability enters the frame.

**Exact protected dependency.** Designing envelopes, state machines, timing tables and canonical manifests with authored data needs no protected access. Proving policy commit/cursor durability and every-writer participation eventually requires separately authorized I-AM authority integration; proving owner/session changes requires their actual authoritative paths. Saved-source delivery needs Lane 1. No second policy database, grant authority or source catalog should be introduced. An in-memory model can qualify ordering logic only, not durable security or remote timing.

**Smallest next increment (L2-A, recommended first).** A bounded authority/capture-delivery architecture contract, with exact source-only authority/writer audit and authored event/resource examples. Reuse the security prerequisite and decide cursor durability feasibility, writer coverage, session/owner/expiry signals, health/visibility/reconnect behavior, deliverable byte identity and realistic timing acceptance. Deliver explicit proposed API/data contracts and negative scenario tables; no store opening, source reads, migrations, implementation or runtime tests. Stop if source access cannot establish the necessary owner contract. Acceptance: one authority per concern, no polling-only revocation claim, complete commit/crash/gap/expiry/replay matrix, explicit unavailable states and separately approvable implementation boundaries. A subsequent pure in-memory contract implementation could then be authorized independently; production security qualification would remain open.

## Lane 3 — native saved renderer and package admission

**Exists.** Accepted fixture execution includes the actual native Card and direct native UibPanel layout with exact data-only schemas; pure route helpers inspect authored parameters. `src/client/fixture-preview/host.ts` uses a fixed hash-admitted bootstrap, opaque sandbox, no connect/resource privileges and validated nonce/session/identity/sequence messages. Existing lifecycle destroys executable content when stale/revoked/disposed. Those bounds remain unchanged. Direct Panel rendering is not canonical Region rendering, and route text inspection is not route execution.

Existing broader native implementations include `mountVisualArtifact`, `mountComposedPage` and `attachFormRuntime` in `packages/visual-artifacts/src/`. The composition renderer projects Regions and applies Menu/theme/branding assets. `runtime.ts` imports the Forms barrel plus Form/composition behavior. `form-runtime.ts` supports initialization and Dataset adapter calls. The prior audit identified recent-value browser-storage helpers in the Forms closure; denial by CSP/sandbox does not itself admit attempted effects.

`src/server/component-registry.ts` discovers package/catalog metadata and live module locations. Legacy `src/client/visual-artifacts/preview.ts` imports installed module URLs, can compile/load function modules and uses live composition asset URLs; its client `design` Boolean and empty services do not establish security. The old Form preview's flush-before-open path is also unsuitable. None should be executed or relabeled as the new protected design host.

**Missing.** Exact per-type admission criteria and finite public contracts; content-hashed executable/resource closure including CSS URL/imports, SVG references, fonts, workers, embeds and dynamic discovery; duplicate tag/version/activation rejection; renderer/policy compatibility; native initialization/hook cleanup and non-effecting behavior. No shim/substitute native dependency, security weakening or new executable package capability is justified.

**Exact protected dependency.** Auditing explicit installed native source text and literal authored schemas can be independent of saved state, provided no registry execution or package import is used for discovery. Actual protected saved definitions, field/schema visibility, owner-qualified references and installed activation/state capture require existing authorities and Lane 1. A definition found only in a protected Component cannot be opened under a source-audit authorization. New module/bootstrap execution needs its own exact admission and verification gate even when it uses synthetic inputs.

**Smallest next increment (L3-A).** Source-only admission audit of one explicitly selected native family and its resolved import/resource/event closure, with authored examples and reject/unavailable reasons. Prefer auditing the smallest declarative Page/Visual path over accumulating more fixture families; if the Forms barrel prevents bounded admission, report the boundary and stop that candidate without modifying native code. Produce exact-path closure, semantic/resource matrix and a decision whether unchanged native execution is feasible. Acceptance: no invented canonical schema, no runtime discovery, no effect-attempt admission merely because the browser denies it, and no claim of saved-artifact support. Only a later authorization may prototype a proven-safe synthetic path.

## Recommended order and future verification boundaries

1. Decide **L2-A** first: authority/currentness and captured-delivery constraints define what any production host may display. L1-A historical/source correlation and L3-A native closure audit are independent follow-on review lanes; they need not wait for an operational recovery. This is an execution sequence proposal, not permission to delegate or start them.
2. After architecture approval, consider one pure authored-data contract increment covering capture manifests and authority/channel state ordering. Its proposed verification would use exact named new files, in-memory authorities/clocks and serial zero-retry runs. No source reader, normal launcher, backend or Foundation tests should enter its closure. Model success would not accept D6, trusted production authority or actual saved capture.
3. If L3-A admits a complete unchanged native path, separately authorize a restricted-host compatibility prototype with authored data and exact bytes. Verify resources, effects, stale/cleanup and editing/autosave preservation. Do not loosen the current host to accommodate an unsafe dependency.
4. Integrate real policy/owner/session authority only under its own reviewed scope, including every-writer durable delivery and accepted timing/health limits. Integrate saved-source capture only after the applicable D6/operational qualification gates. These integrations may be independently blocked; protected activation requires both plus native admission.
5. Then separately authorize actual saved-artifact Preview with exact supported types, coherent capture, immutable delivery, server denial/replay checks, remote invalidation/health races and ordinary Builder preservation. Retain unavailable states for every unsupported type. Effecting tests and Release remain WP5-G/H; integrated readiness remains WP5-I.

No tests are allowlisted for execution by this report. Future proposals must enumerate exact files, transitive imports, setup/build/server paths and expected protected dependencies before authorization. Broad workspace builds/suites, the 55 deferred Foundation tests and ordinary integrated launchers are excluded. Any future protected run needs before/after store evidence within its separately authorized access boundary; this review cannot provide or imply those checks.

**Windows Identity/N01, token/elevation, VM/WinPE and Foundation recovery remain paused.** Existing Windows/publication hypotheses, unresolved-owner records and provenance limitations do not independently justify restarting them. Reconsider only if a specific required production verification cannot proceed, the causal evidence and alternatives are documented, and the user separately authorizes the exact operational action. No current owner/PID/lock inspection, cleanup, quarantine, recovery, OS preparation or token experiment is part of any recommended independent increment.

Stop only the affected lane/candidate on missing or conflicting references, protected-state need, unsupported closure, new authority, altered native/persistence behavior or security-policy weakening. Preserve evidence and continue independent authorized review work. No fixture/model pass should be used to bypass a blocked protected gate.
