# Source Identity Parser Hardening — preimplementation contract

2026-10-25. Established before parser implementation. This extends the existing offset reader and shared validation, not HTML runtime semantics, a second parser or Preview selection.

## Compatibility review

The existing source.ts token reader lowercases tag names, skips comments/declarations, preserves offsets and source bytes, supports quoted values containing greater-than signs, raw script/style/textarea bodies and optional HTML end tags. Attribute extraction previously searched permissively across gaps, kept attribute names case-sensitive, silently overwrote duplicate names, decoded only `&quot;`, `&lt;`, `&gt;`, `&amp;` in that order, and accepted boolean/empty identities until later checks. Cross-node duplicate resulting ids were diagnosed but still returned. Malformed openings could be skipped entirely; validation appended parser diagnostics but continued identity interpretation.

Supported valid source remains offset-preserved: wrappers, ordinary/custom tags, manual regions, optional end tags, comments, raw text bodies, ordinary attributes, and whitespace/single-quoted/double-quoted/unquoted attribute values. Existing focused tests in tests/visual-artifacts.test.ts establish preservation and editing expectations; that mixed test file also executes filesystem/backend discovery, so it is inspected, not executed here. New authored tests isolate its source-only cases. No protected saved sources are used.

## Accepted normalization and refusal rules

Only the two exact ASCII identity names `data-uip-node` and `data-uip-component` are normalized with ASCII A–Z to a–z. One uppercase/mixed-case spelling is recognized; any repeated effective name is an error even if values are identical. Nonidentity attribute casing/last-value behavior is preserved. Node/reference values retain case; values are never case-folded, trimmed or invented. Attribute names are never entity-decoded, Unicode-normalized or interpreted as aliases.

Attribute lexing must consume each opening tag's entire attribute region contiguously, using the same reader. Each attribute needs separating whitespace (`\s`, matching the existing source grammar). Assigned values may be single/double quoted or nonempty unquoted values excluding quotes, backticks, equals and angle brackets. Boolean ordinary attributes remain supported. Names retain the existing broad syntax except angle brackets/backticks/ampersands; encoded names are unsupported, never aliases. Identity attributes require an explicit nonempty value. Existing four named value entities remain supported; other entity spellings in identity values are refused, never newly decoded. Unquoted values adjoining a self-closing slash are refused as ambiguous, preserving the prior rejection of such managed node values. Quoted self-close and whitespace-delimited self-close are supported.

Malformed or incomplete opening tokens get an error through an added refusal alternative in the existing tokenizer. This alternative never creates a managed node. Identity syntax errors, structural errors and cross-node duplicate ids invalidate **all** managed ids and Component references in the parse result. Nodes/offsets/ordinary attributes remain available for manual inspection; cleared nodes are manual. No first/last identity remains usable. Warnings alone (such as missing wrappers/optional end tags) retain existing supported behavior. Raw script/style/textarea bodies stay opaque; identity attributes on those manual raw-text nodes are refused. Comments/declarations are not interpreted as identity markup.

Diagnostics continue to use the existing structured severity/message/node contract. New deterministic error messages identify source offset and refusal category, without publishing an ambiguous id. Shared validateArtifact returns its accumulated diagnostics on parser error before constructing node/reference maps. componentReferences sees the same cleared parser results; no extra scanner is introduced. setNodeAttribute must refuse erroneous documents and match either identity attribute spelling case-insensitively when editing an otherwise valid tag, avoiding accidental duplicate creation.
