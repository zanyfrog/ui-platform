## Interactive metadata and event routing

Card implementation in UI `src/layout/index.js` already emits selection and action events. Use declared stable payload fields such as selected/newValue and action token after verifying each event's actual detail. One selection updates existing local state; declared action maps to existing navigate/set/service/protected-delete action types. Nonserializable original Event references are not persisted as expressions or contracts. Do not attach both generic change and specific selection handlers for the same transition.

Panel already observes collapsible/open and emits `uib-panel-toggle`. Native component behavior owns opening/closing; Platform configures initial/bound state and optionally consumes the state event. Avoid a second toggle handler that immediately reverses the native transition. Preserve focus when collapsing and prevent events escaping the wrong artifact boundary.

Hero `src/uib-hero.js` emits cancelable `uib-hero-cta` plus legacy variant events. Admit the unified event once; expose bounded scalar payload fields including actionToken, ctaType, href and disabled. Reuse `action-components` model/helpers for supported ordered CTA configuration where compatible, retaining existing shared settings as authority. Links use validated href/target/rel; action tokens select an allowlisted application action rather than executable text. The Shell must receive runtime service/navigation context. Verify no duplicate forwarding from inner button and no double navigation. Existing `model.ts` generic action/event mechanisms remain the route, not registered arbitrary handler IDs or new per-Hero executable code.

HTML owns placement, literal values and slots. Existing metadata owns dynamic bindings, source/query configuration, state, conditions/repeaters and declarative actions. Dataset identity/mappings remain Form-owned; I-AM grants never come from component metadata.

Public/private is an authorization/storage property enforced by the server, never picker visibility alone. Retained interfaces must route private assets through the production protected service; private files cannot be copied into public static release output. General reusable asset UI defects belong in Base; Platform owns its transport/path/revision adapter.

Other audit dispositions: use action buttons for new compatible actions, but retain native submit semantics; keep dirty/pending/conflict tab lifecycle rather than blanket tabs conversion; retain native dialogs until focus/top-layer parity; reuse binary checkbox/toggle only where unset is not a third state; retain source/number controls that preserve incomplete values; reuse menu rendering while retaining identity-based authoring. Icons/labels/layout primitives are available, but ordinary semantic HTML/CSS is not a component rewrite obligation. UI Layout's separate autosave/write lifecycle and App Manager's ORM/dev-auth contracts prevent wholesale replacement. These optional cleanups do not block V1.
