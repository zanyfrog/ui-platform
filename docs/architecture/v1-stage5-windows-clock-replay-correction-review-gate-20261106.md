The bounded correction is implemented and verified for the tested Windows-local scope. It awaits project-owner review. This is neither Stage 5 acceptance nor V1 closure. UI baseline `3d6fa162bd37f71e67bcd5962a8d1de42da0c7cd`; accepted Data dependency `d2525592eee4d6286537a7093510e59fd4c342f2`.

## What changed

`internal-jwt-clock.ts` supplies the same Windows OS wall-clock source to Runtime, Data and Management internal signers and verifiers. Each process lazily prepares a single SQLite query in memory. The query rounds binary conversion noise from SQLite's millisecond timestamp; the adapter rejects anything other than a positive safe integer in the Date range. No file, service, background reader, dependency or fallback after failure is added. The source choice is Windows-only; elsewhere the existing Date source remains, with no qualification claimed here.

Each issuer samples once and uses integer `iat` with `exp = iat + 15`. Both receivers give pinned `jose` 6.2.15 explicit `currentDate`, retain the existing max-age, algorithms and claims, then check strict `iat`, expiry, maximum age and `nbf` again after asynchronous signature verification. The actor receiver also checks again after current enrollment/session checks. Final comparisons use the same whole-second convention as the pinned verifier. The transport's former caller-supplied issue-time override is removed; the expired-assertion test now signs its own deliberate negative. No time allowance is added to any claim check.

Replay entries are scoped to the verifier's receiver audience and keyed by the exact issuer/nonce pair. Reservation is synchronous before actor authority awaits. An entry is evictable only when its claim has expired and at least 15 monotonic seconds have elapsed since reservation. At 8,192 retained entries the verifier rejects new assertions rather than evicting still-relevant entries. This can refuse high bursts near the existing cap; tests cover both limits independently. Neither a backward step nor a clock fault purges a live cache or grants acceptance.

Each receiver launch must use a fresh unpredictable audience, distributed to the matching signers through the existing trusted launch configuration. The local integration launcher already generates fresh actor and RPC audiences and keys for every launch. The clock fault is sticky in the process; there is no reset API. Recovery requires a controlled relaunch with fresh audiences and ephemeral session state, after the operator establishes a trustworthy host clock. Reusing an old launch configuration is outside that receiver-epoch contract; no automatic peer rejoin or key-distribution protocol is introduced. Old signing keys are rejected when removed from the configured trust set.

## Discontinuity model and limits

An `hrtime.bigint()` sample brackets each wall read. Reject an invalid reading, a read taking over **64 ms**, any observed raw wall decrease, a monotonic reversal, or a wall delta outside the bracketed elapsed interval plus **64 ms + 1 ms per elapsed second**. The last accepted sample is retained across calls. The extra interval term budgets at most 0.1% relative slew between observations; it is an engineering admission bound for this local candidate, not a measured universal Windows clock bound. The first successful sample initializes the process observation, and does not independently attest host UTC.

A two-second sample in the verified physical target recorded 2,126,742 reads, maximum bracket 0.45 ms, largest wall increment 16 ms and maximum adjacent wall/elapsed difference 15.9999 ms. The fixed bound is four times the largest observed clock increment, allowing for granularity and ordinary short sampling variability. A longer stall or larger disagreement makes internal authentication unavailable under the existing refusal envelopes. Neither bound changes `iat`, `exp`, `nbf`, the verifier's supplied time, replay retention, transport deadlines or proof budgets.

This detects observed decreases and sufficiently large net disagreement, including simulated suspend/resume where elapsed clocks diverge. A step and compensating step entirely between reads, changes that advance both clocks consistently, or disagreement within the admission envelope cannot always be detected. No host time or actual suspend state was changed. For consumed assertions, nonce retention and the observed wall high-water rule jointly prevent resurrection: if a nonce was evicted, the verifier had already observed wall expiry, and a subsequent wall reading that could make that assertion current would be below that observation. A new receiver epoch excludes old audience assertions even when a new clock has no prior observations. This is not a guarantee against an adversary controlling the host's clocks, signing keys or launcher.
