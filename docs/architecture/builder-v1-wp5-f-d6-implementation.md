# WP5-F D6 — implemented admission remediation

2026-10-18. Workstream A implementation authorized by the user after Gate 1 architecture approval. **Implementation review only; D6 is not accepted or closed.** Focused preview, WP5-G and WP6 are not implemented. Gate 2 remains conditional; [security prerequisite investigation](builder-v1-wp5-f-security-prerequisite.md) stops at a separate security architecture decision.

## Change and preserved authority

Foundation retains the existing global `visual-runtime-graph-v1` filesystem lock, PID ownership, recovery lock, role transaction journals, rollback and readback. There is no new lock/storage authority, lease, migration, lock stealing or source format. Existing ordinary Application data services and renderer behavior are unchanged.

`packages/artifacts/src/storage.ts` adds typed source-busy admission, optional acquisition budget/AbortSignal, safe local-queue cancellation, acquisition-only live-owner retries and transient owner-file disappearance handling. A callback runs once after exclusive ownership; an error thrown from that callback never enters the retry loop, even if it is the exact busy-error type. The budget applies to waiting, not admitted work. Cancellation after admission does not interrupt a transaction or rollback. Queue cancellation cannot allow a later caller to bypass an active predecessor.

Async operation context rejects recursive acquisition, role-to-graph order inversion and graph-to-graph nesting. Existing final Visual admission rereads dependencies under the outer graph while holding the target role lock; this accepted check is retained. Such subordinate reads are protected from cooperating graph writers by the outer graph admission. Existing distinct provider-coordination → artifact-source locking in migration/deployment remains permitted: it is not recursive graph admission. An initial blanket rejection of distinct nested locks broke nine migration tests and was removed, with the failed full run retained. This is narrower than the proposal's ideal no-two-role-lock rule; final dependency checks and existing provider coordination must not be deleted to enforce that ideal. No general multi-role transaction or new ordering authority is introduced.

`role-bundle.ts` supplies bounded graph admission to cooperating readers/writers and bounded acquisition at individual explicit-role locks. A snapshot reader outside graph admission may otherwise collide with a cooperating graph reader's short role capture; waiting must occur at that role acquisition, not by replaying the snapshot callback. `runtime-read-admission.ts` delegates once rather than retrying an entire capture on a matching message. `composition-lock.ts` removes its redundant Application promise scheduler: the authoritative global Foundation queue already serializes all Applications, while the second scheduler hid nested entry and had no cancellable waiting. Original Application identity still comes from existing protected services; `_root` is not a new admission identity or permission.

`index.ts` binds request disconnect to acquisition cancellation using an async request scope. This affects queued `withApplicationMutation` work, not an admitted write. Runtime callers can supply an AbortSignal through the shared graph-read API; shared Vite module transforms are not cancelled just because one consuming browser request disconnects. Existing legacy focused-preview helpers are not reworked into the new preview architecture.

## Measured budget and limited critical-section reduction

Before enabling waiting, the two targeted regression fixtures were run with measurement instrumentation. Both encountered the known live-owner rejection. Fourteen successful captured holds reached approximately **1,652 ms**; the telemetry-stage error was typed 503 rather than the original historical generic 409. The original **474/476 — NOT PASSED** records remain unchanged. This new run reproduces the lock-rejection mechanism, not the exact historical response mapping.

The initial graph acquisition budget is **5,000 ms**, with at most **25 ms** between acquisition attempts and one shared deadline covering the local queue plus filesystem contention. This allows roughly three observed long initial holds, rather than replaying requests or extending admitted work. Explicit-role acquisition uses the same five-second budget; unrelated Foundation users retain their default acquisition contract. Exhaustion is a typed `source.busy`/503, distinct from stale source, denied authority, native validation and recovery-required failures. Canonical path checks and filesystem calls themselves are not hard-real-time interruptible; timer scheduling and OS latency can overshoot a nominal deadline. No global fairness guarantee is claimed across independent processes.

The first full run exposed repeated runtime acquisition exhaustion while the Builder maintained a populated local graph queue. Immediate same-process reacquisition repeatedly won the unlink window against a process polling every 25 ms. Queued graph handoffs now yield up to **50 ms** (two polling intervals), within the same deadline, so an already-waiting process has an acquisition opportunity. The existing lock is still the sole admission authority. This is bounded cooperative handoff, not a new FIFO filesystem protocol or a guarantee against arbitrary process scheduling. The five-second budget is not increased to hide the observed failures.

Pure HTML/fixtures/functions/CSS syntax work for normal Visual PUTs is validated before entering graph admission. The exact serialized candidate bytes attest this reuse; changed candidate bytes cause validation again. Application identity, dependency validation, target revision, source rechecks, original authority and the journaled write remain under the existing ordered graph/role admission. No broad detached graph validation/compilation was introduced. Larger capture/Problems section reductions remain deferred until their immutable-input/membership contracts can be proven safely; they are not necessary assumptions for current correctness.

The second browser run still exposed saturation during overlapping reads. The safe reduction is now also applied to capture itself: `VisualArtifactService.read` resolves its location once instead of twice; explicit-role canonicalization deduplicates ancestor checks and runs independent path checks in parallel; collection discovery reads at most four independent bundles concurrently, preserving sorted output and every bundle's lock/recovery/identity checks. Sibling read scopes do not nest or wait on one another, and the outer graph remains held where required. There is no retained source cache, stale substitution, skipped check or parallel journaled multi-artifact write. The affected coherent-reader, source/path safety, recovery and coordination run passed 72/72. A subsequent actual simultaneous browser journey passed with 129 recorded admissions, maximum wait approximately 3.592 seconds and maximum hold approximately 1.607 seconds, with the original five-second budget unchanged. Two acquisitions did not enter and ended after about 0.14–0.16 seconds; the current duration-only telemetry does not label their cause, so they are not presented as successful acquisitions or as proven timeout events.

Opt-in `UI_GRAPH_LOCK_TRACE=1` records PID, wait/hold durations and acquisition result; `UI_GRAPH_LOCK_METRICS` optionally captures JSONL diagnostics to an operator-selected file. It does not log source, artifact paths, User identities or grants. Observer failures cannot change admission results. Measurement occurs through the existing lock, not another coordinator.
