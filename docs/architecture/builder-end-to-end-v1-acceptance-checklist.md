## Completion rules

- The primary acceptance milestone ends with a functioning development Application; A38/A39 protect existing release behavior but do not require publishing that reference Application.
- Ordinary runtime CRUD intentionally writes the reference development store. Focused preview/test writes must use the explicitly isolated test environment. UI labels alone do not establish isolation.
- Roles, Dataset application and host configuration needed for the primary journey cannot be hidden in fixtures. Bootstrap prerequisites and approved services must be declared before the operator starts.
- Missing direct-source/CLI operations remain gaps until closed or explicitly deferred with rationale and review approval. Programmatic test assembly is supplemental evidence only.
- A passing aggregate validation result is not a substitute for protected runtime and actual persisted-data checks.
