# Multi-Page implementation contract notes

2026-10-28. Work in progress; no acceptance claim.

Existing graph boundary: server/index.ts wraps Visual Create, normal Save and Delete in withApplicationMutation. composition-lock.ts delegates to the existing Foundation withRoleBundleGraph on the canonical platform Components root. No second lock is added. Normal candidate validation captures Pages before target role acquisition, validates the complete candidate in saveRoleBundle, and rechecks captured related revisions at admission. Incoming link scans and route uniqueness run within that same graph callback. This establishes serialization among participating Builder operations, not arbitrary filesystem writers or a multi-artifact commit. Repair remains repair; no authorization or recovery behavior changes.

Plain Page route admission is bounded to root or lowercase slug paths; composed Page route admission remains on the existing composition contracts. Unchanged legacy links are not rewritten or newly admitted. Newly introduced or changed root-relative Page links must resolve exactly one valid saved plain Page. Deletion excludes outgoing links in the deleted Page; route changes include surviving self-links in the candidate. Destination choices derive from the authorized workspace listing and write literal href attributes only.

Saved Design Preview URL contract: /visual-preview.html?app=<application key>&locator=<saved locator>&revision=<saved bundle hash>&kind=page&design=1&page=<logical route>. Values are URLSearchParams encoded. The locator/hash identify the saved revision; the route parameter is descriptive and is refreshed from authoritative metadata. The URL fragment retains accepted same-Page anchor meaning. On reload the iframe reads these parameters and uses the existing hash-checked saved Preview endpoint. The parent load message cannot replace an already initialized URL-selected Page. Page links refresh the authorized Page list and resolve a unique saved destination before requesting its exact Preview revision. History is pushed only after successful loading/mounting; popstate reloads the URL-selected revision without pushing. Failed revision reads block rather than substitute draft or recovery data. Parent URL is never written.

Verification separation: isolated DOM fixtures use fake saved transport and do not establish normal authorization. Normal Chrome verification must supply separate evidence. Eight existing anchor-focused tests are included because the shared click/lifecycle path changed, without repeating unrelated native authoring campaigns.
